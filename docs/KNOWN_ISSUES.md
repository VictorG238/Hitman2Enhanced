## Game bugs / limitations (observed)

| ID | Observation | Evidence |
|---|---|---|
| GB-001 | Frame rate is uncapped (menu 1194–5282 fps, in-game 509–1969 fps) although VSync interval 0x1 is requested. At very high frame rates the game freezes / ignores Esc / desyncs cutscenes. Likely cause: the integer game clock adds `trunc(dt*1024)` per frame, i.e. 0 above 1024 fps (TIMING_AND_FPS.md "Frame timer", INFERRED). | EXP-003 run-001/002, 2026-11-11 static |
| GB-004 | Windowed mode centres the window on the whole virtual desktop, so with two monitors it straddles them. Workaround: `StartUpperPos 0,0` in `Hitman2.ini`. | EXP-003 run-005 |
| GB-005 | At 1920x1080 the map screen's mouse hit areas are offset from the drawn labels, and the map content can appear offset/zoomed against its frame (also without any fix). Cause OPEN (engine input mapping). | EXP-003 run-006, run-009 |
| GB-006 | HUD and menus keep their original pixel size (tiny at 1080p); menus and the briefing are a fixed 640x480 panel. Owner wants them scaled up (feature). The engine centres the layout itself in ~15 places without a scale factor; viewport scaling was tried and rejected (RENDERING.md). | EXP-003 run-006, run-009 |
| GB-010 | UI text is pre-rasterised: 128x128 bitmap font pages (4-bit alpha) per scene; magnified by `menuscale` it looks soft. Fix `hdfonts` (EXP-005) swaps in 4x pages re-rendered from the embedded TrueType font; menus/Load/briefing confirmed sharp in game (run 1), subtitles pending. | EXP-005 |
| GB-011 | Crash while loading a save from the main menu (2026-11-11 12:13:34, PID 0x46F4, proxy 0.7.0 working tree with resolution + menuscale + framelimit + hdfonts, log `samples/local/logs/h2e-20261111-121555.log`, ~3 s into the load after Load was chosen): `0xC0000409` fast fail subcode 0x15 (`FAST_FAIL_INVALID_EXCEPTION_CHAIN`: SEH chain on the stack corrupted when an exception was dispatched) in ntdll+0x7A15C, then an access violation at 0xFFFFFFFF. Owner: the same save had loaded fine before. Same family as GB-008 (original game, no proxy: 0xC0000409 then 0xC0000029 while loading a mission) - `HYPOTHESIS` a pre-existing engine stack corruption during loads; the proxy (menuscale memory scan, GB-009; hdfonts texture memory) is not excluded. WER folders need admin rights; no dump. Run 3 (15:41, same fixes and save): loaded without crash; hdfonts frees its copies at every scene change (max 19 live), so it does not accumulate memory. Not reproducible so far. | Windows Application log |
| GB-008 | Crash while loading a mission (2026-11-11 00:20, original game, no proxy, windowed 1920x1080): exception 0xC0000409 in ntdll.dll +0xC60C7, then 0xC0000029. No error.log or dump. Cause OPEN. | Windows Application log |
| GB-009 | Two crashes while loading a saved game from the main menu (2026-11-11, proxy 0.7.0 commit 8a7e5b5: timer + menuscale with the IngameMap probe + framelimit): 11:21:00 access violation at hitman2.exe+0x212645 (`cmp ebp,[ebx+9]`, method on an invalid object); 11:21:16 breakpoint 0x80000003 at hitman2.exe+0x1B8B5E (engine container consistency check, int3 when no assert handler) followed by an AV. GB-008 in the original game). Mitigation: chunked scans into a static 64 KB buffer, at most 3 map scans per scene. **Recurred** 2026-11-11 16:44:52 (PID 0x41C, commit 63241f4 build, resolution + menuscale + framelimit + hdfonts, **timer off**; NPC A/B run B): same AV at hitman2.exe+0x212645, ~3 s into a save load from the main menu (log: main-menu ZWINDOWS gone, load-screen font pages created, then nothing).
